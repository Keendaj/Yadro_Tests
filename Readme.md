# 📊 System Data Collector

Приложение для мониторинга системных метрик хост-машины в реальном времени с клиент-серверной архитектурой. Использует **Unix Domain Sockets (UDS)** для межпроцессного взаимодействия и **WebSockets** для передачи данных в веб-интерфейс.

---

## 🛠 Технологический стек

* **Backend:** C++17, CMake, `nlohmann/json`, POSIX Threads.
* **Frontend:** Node.js, TypeScript, Vite, Express, WebSockets (`ws`), `Chart.js`.
* **Инфраструктура:** Docker, Docker Compose, Многостадийная сборка (Multi-stage builds).

---

## 🏗 Архитектура проекта и потоки данных

Проект разделен на два независимых микросервиса, работающих в единой связке:

1. **Хост-машина (`/proc`):**
   * Является первоисточником данных. Контейнер бэкенда запущен с директивой `pid: "host"`, что открывает ему полный доступ к реальным метрикам операционной системы хоста.

2. **Бэкенд (`DataCollectorBackend`):**
   * **Сбор метрик:** Напрямую парсит файлы виртуальной файловой системы `/proc` (`/proc/stat`, `/proc/meminfo`, `/proc/[pid]/stat`).
   * **Расчет дельты (Stateful):** Сохраняет состояние предыдущих тиков процессора, вычисляя точный процент загрузки CPU и процессов между секундными интервалами.
   * **UDS-сервер:** Раз в секунду сериализует метрики в JSON и транслирует пакет через Unix Domain Socket (`/tmp/system_data.sock`).

3. **Связующий слой (Docker Volume):**
   * Контейнеры делят между собой `sockets_volume`, примонтированный в директорию `/tmp`. Это позволяет изолированным средам общаться по локальному сокету без сетевых накладных расходов.

4. **Фронтенд и Прокси-сервер (Node.js):**
   * **UDS Клиент:** Подключается к Unix-сокету бэкенда и непрерывно принимает поток системных данных.
   * **WebSocket Сервер:** Перенаправляет (проксирует) полученный JSON-поток всем подключенным пользователям в реальном времени.

5. **Клиентская часть (Браузер):**
   * Принимает данные по протоколу WebSocket.
   * Динамически строит и обновляет графики загрузки процессора и ОЗУ при помощи `Chart.js`, а также выводит интерактивную таблицу активных процессов.

## 📂 Структура репозитория

```text
├── backend/
│   ├── utils/                # Вспомогательные структуры, логирование, сериализация

│   ├── data_collector.cpp/hpp# Логика чтения и парсинга /proc
│   ├── server.cpp/hpp        # Реализация UDS-сервера
│   ├── main.cpp              # Главный цикл приложения
│   └── Dockerfile            # Многостадийная сборка бинарного файла
├── frontend/
│   ├── src/                  # Исходный код клиентской части (TypeScript, CSS)
│   ├── server.js             # Сервер Express и WebSocket-прокси
│   ├── package.json          # Зависимости и скрипты Node.js
│   └── Dockerfile            # Сборка статики и запуск Node-сервера
└── docker-compose.yml        # Оркестрация и конфигурация volumes/network
```

## 🚀 Быстрый запуск

Убедитесь, что в вашей системе установлены **Docker** и **Docker Compose**.

1. Клонируйте репозиторий и перейдите в его корневую директорию.
2. Для автоматической сборки и старта всех компонентов выполните команду:
   ```bash
   docker compose up --build
   ```
   *(Если вы хотите запустить контейнеры в фоновом режиме, добавьте флаг `-d`)*

3. После успешного развертывания панель мониторинга будет доступна по адресу:
   👉 **http://localhost:8080**

## 📖 Генерация документации кода

Исходный код бэкенда снабжен подробными комментариями в формате Doxygen. Вы можете локально сгенерировать интерактивную HTML-документацию.

### Предварительные требования
Убедитесь, что в вашей системе установлен утилита `doxygen`.
* На Ubuntu/Debian:
  ```bash
  sudo apt update && sudo apt install doxygen graphviz
  ```
* На macOS (через Homebrew):
  ```bash
  brew install doxygen graphviz
  ```

### Сборка документации
1. Перейдите в директорию бэкенда:
   ```bash
   cd backend
   ```
2. Запустите генератор Doxygen:
   ```bash
   doxygen Doxyfile
   ```
3. После завершения процесса в папке `backend/` появятся директории `html/` и `latex/` (в зависимости от настроек конфигурационного файла). 
4. Откройте файл `html/index.html` в любом браузере для просмотра интерактивной документации по классам и методам архитектуры бэкенда.

## 🛑 Остановка и удаление

Чтобы остановить работу сервисов и полностью очистить созданные сокеты и volumes, выполните:

```bash
docker compose down -v
```
